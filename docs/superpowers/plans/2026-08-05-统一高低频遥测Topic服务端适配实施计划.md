# 统一高低频遥测 Topic 服务端适配 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 服务器直接切换到 RPi 统一的快照与实时遥测 Topic，仅将 schema v3 快照入库，并按浏览器兴趣精确订阅 schema v1 实时帧。

**Architecture:** `route_service` 只通配订阅 `telemetry/snapshot/v1`，沿用现有设备状态与入库链路。`backend_service` 通过 WebSocket 会话兴趣引用计数驱动 MQTT 精确订阅，把通用实时帧只转发给正在查看该设备的页面。前端通用实时 Hook 合并快照与最新帧，PX4 RTT 保持为独立能力。

**Tech Stack:** C++23、CMake、doctest、libmosquitto 2.0.22、TypeScript 5.5、Node.js 20、MQTT.js 5、Fastify 4、Zod 3、React 18、Vitest 2。

## Global Constraints

- 新快照 Topic 固定为 `cns_rpi/{device_id}/telemetry/snapshot/v1`，`schema_version` 必须为 `3`、QoS 0、`retain=false`。
- 新实时 Topic 固定为 `cns_rpi/{device_id}/telemetry/realtime/v1`，`schema_version` 必须为 `1`、QoS 0、`retain=false`。
- 不订阅、不解析、不保留 `cns_rpi/{device_id}/telemetry` 和 `cns_rpi/{device_id}/px4/realtime/v1` 兼容别名。
- 实时帧不写 PostgreSQL，不建立历史表，不增加数据库迁移，不做数据库备份。
- 实时 `telemetry` 是开放 JSON 对象，可同时携带主控箱 `motor` 和 PX4 动态字段；服务器不按 `device_type` 分流或拒绝字段。
- 主题与 payload 的 `device_id` 必须一致；设备 ID 继续使用现有 `DeviceIdSchema`/`IsValidDeviceId`。
- 前端同一绘制周期只应用最后一帧，2 秒无新帧后回退到最新快照。
- PX4 RTT Topic 和事件保持不变：`px4/latency/probe/v1`、`px4/latency/ack/v1`、`px4.latency_ack`。
- 功能实施从最新 `main` 创建隔离 worktree 和功能分支；提交主题使用 `<type>: <简短中文说明>`。

- [ ] **Step 3: 实施串行目标集合收敛器**

收敛器保持 `desired`、`applied`、`connected` 和唯一 `reconcilePromise`；每次操作后重新比较集合，直到一致：

```ts
export class RealtimeTopicSubscriptions {
  private readonly desired = new Set<string>();
  private readonly applied = new Set<string>();
  private connected = false;
  private reconcilePromise: Promise<void> | null = null;
  private rerun = false;

  setConnected(connected: boolean): void {
    this.connected = connected;
    if (!connected) this.applied.clear();
    else void this.schedule();
  }

  async setDesired(deviceId: string, interested: boolean): Promise<void> {
    if (interested) this.desired.add(deviceId);
    else this.desired.delete(deviceId);
    await this.schedule();
  }

  async settle(): Promise<void> {
    await this.schedule();
  }
}
```

`schedule()` 在已有循环时只置 `rerun=true`；`reconcile()` 先 unsubscribe `applied - desired`，再 subscribe `desired - applied`。交错变更期间回调成功后仍要再比较一次，使迟到 subscribe 最终被 unsubscribe。传输失败时调用 `onError(operation, topic, error)` 一次并停止当轮，避免紧循环。
