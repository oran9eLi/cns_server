# PX4 专属 Web 低延迟链路部署

## 结论

本实现保留现有主控箱全部功能，并为真实 PX4 飞控增加独立控制台和独立实时通道。
新通道只转发到正在查看对应 PX4 的浏览器，不进入 PostgreSQL。

| 项目 | 主控箱 | PX4 真实飞控 |
| --- | --- | --- |
| 原设备列表、状态、数据库 | 保持不变 | 保持，作为慢照和回退 |
| 原 `device.state` WebSocket | 保持不变 | 保持 |
| 新高频 MQTT | 不发送 | 默认 20 Hz、QoS 0 |
| Web 页面 | 原控制台 | PX4 专属控制台 |
| 原主控箱私有命令 | 保持不变 | 明确隔离，不发送 |

## 数据路径

```mermaid
sequenceDiagram
    participant F as PX4
    participant R as 树莓派
    participant M as Mosquitto
    participant B as backend_service
    participant W as PX4 Web 页面
    F->>R: MAVLink
    R->>M: px4/realtime/v1 (QoS 0)
    W->>B: px4.subscribe(device_id)
    M->>B: 高频紧凑帧
    B->>W: px4.realtime
    Note over B,W: 缓冲超过阈值时丢旧帧
```

浏览器离开 PX4 页面后发送 `px4.unsubscribe` 并关闭专用 WebSocket。主控箱页面和设备
列表不会收到 PX4 高频帧。

## 上线顺序

为保证任一步失败都不影响现网，按以下顺序部署：

1. 先备份服务器当前配置和构建产物。
2. 部署 `backend_service` 和 `frontend`。
3. 验证设备列表、主控箱详情、主控箱命令仍正常。
4. 再部署树莓派 `cns_rpi`。
5. 打开真实 PX4 设备，页面应从“1 秒遥测回退”自动切换到“PX4 高频链路”。

服务器无需修改 MQTT 地址、PostgreSQL schema、Nginx `/ws` 配置或 `route_service`。

## 服务器构建与重启

```bash
npm ci
npm run typecheck
npm test
npm run build
```

部署时继续复用现有 systemd 服务和 Nginx 静态目录。重启后检查：

```bash
systemctl status cns-backend-service --no-pager
journalctl -u cns-backend-service -n 100 --no-pager
```

## 树莓派构建与重启

```bash
cmake -S . -B build
cmake --build build -j2
ctest --test-dir build --output-on-failure
sudo systemctl restart cns-rpi
journalctl -u cns-rpi -n 100 --no-pager
```

树莓派配置可显式加入：

```json
{
  "px4_realtime": {
    "enabled": true,
    "publish_interval_ms": 50
  }
}
```

旧配置不含该段也会对真实飞控默认启用；主控箱不会发送该 topic。

## 页面指标

- `Web↔树莓派真实 RTT`：浏览器发出探测到收到树莓派 ACK 的应用层往返时间。
- `P50`：最近 30 个有效 RTT 样本的中位水平。
- `P95`：最近 30 个有效 RTT 样本中覆盖 95% 情况的上界，更适合判断 5G 波动。
- `抖动`：当前按 `P95 - P50` 显示。
- `Hz`：浏览器最近约 2 秒实际接收频率。
- `丢弃帧`：根据 `sequence` 缺口累计。

RTT 探测链路为：

```text
浏览器 → HTTP → backend_service → MQTT → 树莓派
       ← WebSocket ← backend_service ← MQTT ← ACK
```

探测和 ACK 使用 QoS 0、不 retain、不进 PostgreSQL，也不复用主控箱控制 topic。开始和
结束都使用同一浏览器的 `performance.now()`，所以不依赖树莓派、服务器、Windows 三端
时钟同步。这个 RTT 不包含 PX4 到树莓派的 USB/MAVLink 采集时间。

对应 MQTT topic：

```text
cns_rpi/{device_id}/px4/latency/probe/v1
cns_rpi/{device_id}/px4/latency/ack/v1
```

页面每 2 秒最多发一个探测，5 秒未返回计为一次超时，不会形成积压。

## 页面布局

- 飞行仪表和地图使用整行宽度。
- 四张关键指标卡位于地图下方。
- 链路诊断和提示横向排列，窄屏自动改为单列。
- 原始遥测帧默认折叠，展开后才占用页面高度。

## 回滚

### 只关闭高频链路

树莓派设置：

```json
{
  "px4_realtime": {
    "enabled": false
  }
}
```

重启后 Web 自动使用原 1 Hz 慢照，其他功能不变。

### 回滚服务器版本

先关闭树莓派高频发布，再恢复上一版后端和前端。数据库没有新增表或迁移，无需回滚
数据。

## 延迟预期

应用自身新增等待由原来最多约 1000 ms 降为约 50 ms 发布周期，加上 5 ms 串口等待和
WebSocket 推送。真实 RTT 仍由公网 5G、WireGuard/MQTT 路径和两端负载决定，
不能仅靠软件保证始终低于 50 或 80 ms；弱网时本实现优先丢旧帧，避免延迟持续累积。
