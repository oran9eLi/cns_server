# 命令路由可观测日志设计

日期：2026-07-21  
状态：已确认，待实施

## 1. 目标

在不输出请求 ID、命令 ID、原始 JSON 和 MQTT topic 的前提下，为配置命令和飞控命令增加简洁的业务日志，使现场人员能够直接看出：

- 命令来自哪个固定来源；
- 收到的具体命令或配置变更是什么；
- 命令最终路由至哪所学校的哪台设备；
- 设备返回了什么业务应答；
- 应答最终转发回哪个固定来源。

本次只增强日志可观测性，不修改 MQTT 协议、命令状态机、数据库结构、权限规则或 ACK 内容。

## 2. 日志策略

每条正常命令链路输出两类 `INFO` 日志：

1. 设备命令的 MQTT QoS 发布完成，并且命令状态成功持久化为 `dispatched` 后，记录命令路由日志。
2. 设备 ACK 解析成功、相应状态成功持久化，并已提交来源 ACK 发布后，记录应答回程日志。

不在刚收到 MQTT 请求时输出成功日志，避免把非法请求、重复请求、权限拒绝或数据库失败误写为已成功路由。既有异常、拒绝、超时和发布失败诊断保持不变。

## 3. 日志格式

飞控命令路由示例：

```text
[2026-07-21 14:30:25.123] [INFO ] 收到来自 web-console 的飞控命令 takeoff，已路由至设备 SEU / DCDW-001（DCDWCNS1S2MEAG1VTA0C）
```

配置命令路由示例：

```text
[2026-07-21 14:30:25.123] [INFO ] 收到来自 web-console 的配置命令 telemetry_publish_interval_ms=1000，已路由至设备 SEU / DCDW-001（DCDWCNS1S2MEAG1VTA0C）
```

设备应答回程示例：

```text
[2026-07-21 14:30:25.456] [INFO ] 收到来自设备 SEU / DCDW-001（DCDWCNS1S2MEAG1VTA0C）的应答 accepted，已转发至 web-console
```

飞控 `in_progress` 应答及其后的终态应答分别记录，因为两者均会实际转发给命令来源。

## 4. 字段来源与显示规则

- 来源显示经过 topic 解析并在来源目录中验证的 `source_id`。
- 学校名、设备内部编号和 `vendor_id` 取自路由服务已经解析的目标设备记录，不使用请求 JSON 提供的字段拼接显示名称。
- 设备显示格式优先为 `学校名 / 设备内部编号（vendor_id）`。
- 设备内部编号缺失时显示 `学校名 / 未登记编号（vendor_id）`。
- 若内存设备记录异常缺少学校信息，显示 `未知学校 / 设备内部编号（vendor_id）`，并保留 `vendor_id` 以便定位。
- 飞控命令显示协议动作名；`set_motor_pwm` 同时显示四路 PWM 参数。
- 配置命令只显示经过协议解析的实际变更字段和值；多个字段使用中文逗号分隔。
- 设备 ACK 只显示解析后的业务状态，例如 `applied`、`accepted`、`in_progress`、`rejected` 或 `timeout`。
- 日志不得包含 `request_id`、`command_id`、原始 payload 或完整 MQTT topic。

## 5. 实现边界

日志内容由命令业务编排层生成，因为该层同时掌握可信来源、解析后的命令、解析后的设备 ACK、目标设备记录和数据库状态转换结果。运行环境只提供现有日志输出能力，不在 MQTT 适配层重复解析业务 payload。

新增成功日志使用独立的信息级回调，与现有错误诊断回调分开，避免为了记录正常业务事件而把信息写入错误流。日志生成失败不得改变命令状态、阻止 ACK 回程或导致服务退出。

幂等请求若只返回既有状态、不重新向设备下发，不重复输出“已路由”日志；只有本次实际完成设备命令发布并成功持久化 `dispatched` 才记录。迟到 ACK、无法关联的 ACK 和格式非法 ACK 不输出成功回程日志。

## 6. 测试与验收

自动化测试至少覆盖：

- 配置命令成功路由时记录来源、变更字段、学校、内部编号和 `vendor_id`；
- 飞控命令成功路由时记录具体动作，PWM 命令记录参数；
- 设备 ACK 成功回程时记录学校、内部编号、`vendor_id`、业务状态和目标来源；
- `in_progress` 与终态 ACK 分别记录；
- 幂等查询回放不重复记录路由成功；
- 发布失败、非法 ACK 和无法关联 ACK 不记录成功日志；
- 成功日志不包含请求 ID、命令 ID、原始 JSON 或完整 topic；
- 缺少设备内部编号或学校信息时按降级格式输出；
- 日志回调异常不影响命令状态机和 ACK 回程。

本机单元测试通过后，使用现有临时 PostgreSQL、Mosquitto 和真实树莓派链路验证日志显示。真实飞控动作仍需单独安全授权；没有授权时可使用配置命令完成端到端验收。
