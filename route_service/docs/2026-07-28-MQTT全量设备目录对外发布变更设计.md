# MQTT 全量设备目录对外发布变更设计

日期：2026-07-28
状态：设计已确认，待编写实施计划和编码

## 1. 变更背景

现有 MQTT 对外接口通过：

```text
cns_rpi/events/devices/online
```

发布当前在线设备的 `vendor_id` 集合。软件部尚未按该协议正式接入，因此本次不承担旧协议兼容义务，可以直接调整 topic 和消息结构。

Route Service 启动时已经把 PostgreSQL 中的全部已登记设备加载到内存。第一版设备规模预计不超过 1,000 台，没有必要让软件部通过在线集合和历史 retained 单设备消息反推完整设备清单。

本次变更把“在线设备目录”升级为“全量设备目录”，直接发布所有已入库设备的基础资料和当前在线状态。

## 2. 目标

- 软件部只订阅一个 retained 目录 topic，即可获得全部已入库设备。
- 每个目录项明确携带 `online` 或 `offline`，不再用设备是否存在于数组中隐式表达在线状态。
- Route Service 启动或 MQTT 重连后，能够仅依赖内存快照重建全部对外 retained 数据。
- Broker retained 数据被清理或 Broker 更换后，离线设备仍能重新对外出现。
- 对外协议不暴露软件部无业务用途的数据库内部 `school_id`。
- 高频遥测继续只更新单设备 topic，不引起全量目录高频发布。

## 3. 不在本次范围内

- 不修改 PostgreSQL 表结构和内部 `school_id` 使用方式。
- 不开放历史遥测查询和断线期间逐帧补发。
- 不开放配置命令、飞控命令和命令 ACK。
- 不增加分页目录、分片 topic 或遥测聚合窗口。
- 不实施 MQTT TLS、账户和 ACL。

## 4. Topic 设计

### 4.1 全量设备目录

新 topic：

```text
{namespace}/events/devices/directory
```

当前命名空间下为：

```text
cns_rpi/events/devices/directory
```

发布属性：

| 属性 | 值 |
|---|---|
| QoS | `1` |
| retained | `true` |
| 消息形式 | 全量快照 |

旧 topic：

```text
cns_rpi/events/devices/online
```

停止使用，不提供兼容发布。部署新版本时必须一次性删除 Broker 中该 topic 的旧 retained 消息，避免客户端继续读取已经不会更新的在线目录。

### 4.2 单设备当前状态

单设备 topic 保持不变：

```text
{namespace}/events/devices/{vendor_id}/state
```

软件部如需一次接收所有设备状态，继续订阅：

```text
cns_rpi/events/devices/+/state
```

## 5. 全量设备目录协议

### 5.1 消息示例

```json
{
  "schema_version": 1,
  "event_type": "device_directory_snapshot",
  "generated_at": "2026-07-28T05:00:00.000Z",
  "revision": 8,
  "devices": [
    {
      "vendor_id": "DCDWCNS1S2MEAG1VTA0C",
      "school_name": "SEU",
      "dcdw_label": "DCDW-001",
      "model_version": "CNS v1.0",
      "status": "online"
    },
    {
      "vendor_id": "DCDWCNS1S2MEAG1VTA0D",
      "school_name": "SEU",
      "dcdw_label": "DCDW-002",
      "model_version": "CNS v1.0",
      "status": "offline"
    }
  ]
}
```

没有已入库设备时必须发布：

```json
{
  "schema_version": 1,
  "event_type": "device_directory_snapshot",
  "generated_at": "2026-07-28T05:00:00.000Z",
  "revision": 1,
  "devices": []
}
```

不得用零长度 retained 消息表示空目录。

### 5.2 字段定义

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `schema_version` | integer | 是 | 全量目录结构版本，第一版固定为 `1` |
| `event_type` | string | 是 | 固定为 `device_directory_snapshot` |
| `generated_at` | string | 是 | Route Service 生成快照的 UTC RFC 3339 毫秒时间 |
| `revision` | integer | 是 | 当前进程内的目录版本 |
| `devices` | object[] | 是 | 所有已入库设备，按 `vendor_id` 字典序排列 |

目录项字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `vendor_id` | string | 是 | 设备全局唯一标识 |
| `school_name` | string | 是 | 学校名称 |
| `dcdw_label` | string/null | 是 | 校内设备编号；尚未获得时为 `null` |
| `model_version` | string | 是 | 设备型号或协议模型版本 |
| `status` | string | 是 | `online` 或 `offline` |

`school_id` 是 Route Service 和 PostgreSQL 的内部关联标识，对软件部没有稳定业务语义，不得出现在全量目录消息中。

软件部必须把每条目录消息视为完整快照，使用 `devices` 整体替换本地设备目录，不得将其解释为增量变化列表。

## 6. 单设备状态协议调整

单设备状态消息继续携带设备基础资料、当前状态和最新完整遥测，但删除对外 `school_id`：

```json
{
  "schema_version": 1,
  "event_type": "device_state",
  "event_at": "2026-07-28T05:00:01.125Z",
  "revision": 590,
  "vendor_id": "DCDWCNS1S2MEAG1VTA0C",
  "school_name": "SEU",
  "dcdw_label": "DCDW-001",
  "model_version": "CNS v1.0",
  "status": "online",
  "last_seen_at": "2026-07-28T05:00:01.120Z",
  "telemetry_received_at": "2026-07-28T05:00:01.120Z",
  "latest_telemetry": {},
  "change_reason": "telemetry",
  "degraded": false
}
```

删除仅限 MQTT 对外 JSON。`DeviceRecord.school_id`、数据库外键、校内编号唯一性约束和命令寻址继续保留。

因为软件部尚未正式接入，本次直接修改第一版对外协议，不为旧 `school_id` 字段保留兼容期。

## 7. 发布行为

### 7.1 启动和 MQTT 重连

Route Service 从 PostgreSQL 加载全部设备并完成在线超时修正后，在 MQTT 业务连接就绪时发布：

1. 一条完整的 retained 全量设备目录；
2. 每台已入库设备的一条 retained 单设备当前状态。

这里包括在线和离线设备。离线设备状态可以携带最后一次有效遥测，但必须明确设置 `status=offline`。

该行为保证 Broker retained 数据丢失后，Route Service 只需重连即可重建完整对外视图。

### 7.2 目录重新发布条件

出现以下变化时，目录 `revision` 递增并重新发布完整目录：

- 新设备完成入库并进入内存设备目录；
- 设备状态在 `online` 与 `offline` 之间变化；
- `school_name` 变化；
- `dcdw_label` 从空值补齐或发生有效变化；
- `model_version` 变化。

以下情况不重新发布全量目录：

- 普通遥测只改变姿态、电池、位置、链路和其他实时字段；
- `last_seen_at` 或 `telemetry_received_at` 更新；
- 收到不改变目录字段的重复 registration；
- 数据库降级状态变化。

目录发布器应比较目录项稳定视图，不能因为收到每帧遥测就无条件发布全量目录。

### 7.3 设备离线

设备主动离线或活动超时后：

1. 更新内存设备状态为 `offline`；
2. 发布包含该设备且 `status=offline` 的新全量目录；
3. 发布该设备的 retained 离线状态快照；
4. 保留最后遥测，但软件部不得把离线设备的最后遥测解释为当前实时值。

设备不会因为离线而从全量目录删除。

## 8. 一致性与版本

- 全量目录 `revision` 只在目录内容变化时递增。
- Route Service 重启后允许从新的初始版本开始，`revision` 不是跨进程永久序号。
- QoS 1 允许重复交付；客户端收到目录消息时可以使用 `revision` 辅助去重。
- 单设备状态继续使用 `vendor_id + revision` 在同一 Route Service 运行期间去重。
- 全量目录和单设备状态属于不同 topic，不保证跨 topic 严格到达顺序。
- 对在线状态发生短暂不一致时，全量目录是设备清单和在线状态的权威快照；单设备状态随后用于补充完整遥测。

## 9. 容量与性能

第一阶段按不超过 1,000 台设备设计：

- 全量设备已经常驻 Route Service 内存，不增加数据库查询。
- 目录项只包含稳定基础资料和在线状态，单条消息预计为几十 KB 量级。
- 全量目录只在低频目录字段变化、服务启动和 MQTT 重连时发布。
- 高频遥测仍按设备 topic 分流，不触发全量目录重发。

因此当前方案不会形成明显数据库或 Broker 压力。设备数量显著超过 1,000 台后，再根据实测 payload 大小、目录变化频率和客户端解析耗时决定是否分页或分片。

## 10. 代码边界

后续实施需要调整：

- `core/device/device_registry`：增加按 `vendor_id` 排序的全部设备只读快照接口。
- `core/mqtt_topic/device_topic`：用 `DeviceDirectoryTopic` 替换 `OnlineDevicesTopic`。
- `core/state_event/state_event`：增加目录项结构和全量目录序列化；单设备状态序列化删除 `school_id`。
- `core/runtime/device_service`：启动和重连快照从“仅在线设备”改为“全部设备”。
- `service_environment`：维护稳定的全量目录视图，仅在目录字段变化时发布。
- 单元测试和集成测试：同步新 topic、新 JSON、全部设备重放和旧 retained 清理要求。

本次不需要数据库迁移。

## 11. 部署迁移

新版本部署后执行一次旧 retained 清理：

```bash
mosquitto_pub \
  -h 127.0.0.1 \
  -p 1883 \
  -t 'cns_rpi/events/devices/online' \
  -r \
  -n
```

必须先验证新服务已经在：

```text
cns_rpi/events/devices/directory
```

发布正确的 retained 全量目录，再清理旧 topic。该清理只删除一条 MQTT retained 消息，不删除数据库设备、单设备状态或遥测。

## 12. 测试要求

### 12.1 单元测试

- 全量目录 topic 生成正确，旧在线目录 topic 不再作为对外接口使用。
- 空数据库生成 `devices=[]`。
- 全部设备按 `vendor_id` 稳定排序。
- 在线和离线设备同时存在于目录，且 `status` 正确。
- 目录和单设备状态均不包含 `school_id`。
- 目录字段未变化时不递增版本、不重复发布。
- 状态或目录基础字段变化时递增版本并发布。
- 普通在线遥测不重复发布全量目录。
- 启动和 MQTT 重连快照包含全部设备，而不只包含在线设备。
- 目录和单设备状态均使用 QoS 1、retained。

### 12.2 本机集成测试

使用本机 Mosquitto 和测试数据库验证：

1. 准备至少一台在线设备和一台离线设备，且不清空已有数据。
2. 启动 Route Service，订阅者立即收到包含两台设备的 retained 目录。
3. 通配符订阅立即收到两台设备的 retained 单设备状态。
4. 普通遥测只更新对应单设备状态，不发布新目录。
5. 设备上线或离线时收到新目录。
6. 重启 Broker 并恢复 Route Service 连接后，目录和全部单设备状态被重建。

### 12.3 硬件服务器验收

硬件服务器拉取对应提交后验证：

- PostgreSQL、Mosquitto、Route Service 和现有设备数据不被清空。
- 公网 `112.124.52.232:1883` 能立即取得新 retained 全量目录。
- 公网通配符订阅能取得在线和离线设备的 retained 状态。
- 真实设备遥测不会造成全量目录逐帧发布。
- 旧 `cns_rpi/events/devices/online` retained 消息已经删除。
- 现有配置命令和飞控命令路由不受影响。

## 13. 验收标准

- 软件部无需数据库账号即可获得所有已入库设备及其当前在线状态。
- 软件部不依赖数据库内部 `school_id`。
- Broker retained 数据被清理后，Route Service 重连可以重建完整设备视图。
- 软件部能从目录建立设备列表，并从单设备 topic 获取最新完整遥测。
- 离线设备继续保留在目录中，且不会被误表示为在线。
- 1,000 台以内不引入分页、分片和额外数据库读取。
- 旧在线目录 retained 消息在部署时完成清理。
