# 路由服务 V1 全局实施计划

版本：2026-07-18

状态：全局路线已确认；各里程碑须另行完成设计、计划和验收

## 1. 目的

本文是 `route_service` V1 的全局实施路线，不作为一次性连续执行的详细任务清单。完整架构和协议边界见同目录 `2026-07-18-路由服务V1设计.md`。

V1 是跨 MQTT、PostgreSQL、命令状态机和现场部署的较大工程，必须拆成可独立验证、可独立合入 `main` 的里程碑。不得在一个功能分支中一次实现全部 V1。

## 2. 固定开发流程

每个里程碑严格执行：

```text
从最新 main 重建隔离工作树
  → 阅读全局设计、全局计划和相关设备端协议
  → 编写本里程碑设计文档
  → 用户逐节确认设计
  → 编写本里程碑详细实施计划
  → 用户确认实施计划
  → 按 TDD 分任务实现并频繁提交
  → 本机验证
  → 必要时经授权执行现场验证
  → 同步全部相关文档和验证记录
  → 完成里程碑验收
  → 合入 main
  → 删除或归档该工作树
```

只有前一里程碑完成验收并合入 `main`，才能从新的 `main` 编写下一里程碑设计与实施计划。不得预先为后续里程碑编写会约束实现细节的大型执行清单。

全局设计和全局计划直接放在 `route_service/docs/`。每个里程碑自己的设计、详细实施计划和验证记录使用“`YYYY-MM-DD-中文主题.md`”命名，分别放入：

```text
route_service/docs/superpowers/specs/
route_service/docs/superpowers/plans/
route_service/docs/change_history/
```

## 3. 里程碑一：工程基础与数据库骨架

### 目标

建立可构建、可测试、可配置的 C++23 route_service 骨架，以及版本化 PostgreSQL 迁移能力，为后续业务提供稳定接口。

### 范围

- CMake、C++23、doctest 基础工程。
- 中文日志、JSON 配置和有界消息队列。
- libmosquitto 与 libpqxx 依赖探测和最小封装边界。
- `schools`、`devices`、`device_latest_states`、`command_sources`、`commands` 的首版 DDL。
- 迁移版本表、迁移规划器和 `--migrate-only` 入口。
- 示例配置与本机纯逻辑测试。

### 不包含

- 实际设备注册、遥测或命令业务。
- 现场安装 PostgreSQL、修改 Mosquitto 或部署 systemd。

### 完成条件

- 本机 CMake 构建和单元测试通过。
- 迁移文件通过静态与纯逻辑测试。
- 现场依赖验证若未获授权，明确记录为未验证。
- 本里程碑文档与代码合入 `main`。

## 4. 里程碑二：设备注册与最新状态

### 前置条件

里程碑一已合入 `main`，从最新 `main` 重建工作树。

### 目标

完成设备发现、最新遥测、在线状态和规范化实时事件链路。

### 范围

- 在 `cns_rpi` 独立里程碑/提交中将 telemetry 改为 QoS 0、`retain=false`，同步设备端测试和文档。
- retained registration 解析和局部 upsert。
- 首次注册创建学校、设备、最新状态和设备来源。
- registration 主更新、`telemetry.identity` 仅补空的 `dcdw_label` 规则。
- 学校不可自动迁移、同校角色号唯一冲突处理。
- 最新遥测 JSONB 内存快照和默认 5 秒批量落库。
- 服务器接收时间、默认 180 秒离线兜底。
- QoS 0、非 retained 的规范化实时状态事件。

### 完成条件

- 本机协议、状态机、批量合并和离线判定测试通过。
- 两个仓库的 retain 和身份补全说明一致。
- 经授权后完成 registration/telemetry/PostgreSQL/Mosquitto 集成验证；未授权项明确记录。
- 两个仓库分别完成里程碑验收并合入各自 `main`。

## 5. 里程碑三：固定来源与配置命令

### 前置条件

里程碑二已合入 `main`，从最新 `main` 重建工作树。

### 目标

完成固定来源登记、寻址、权限、来源幂等、配置命令路由和 ACK 回程。

### 范围

- 设备来源自动登记和上下线行为。
- host_app、control_center 的部署配置同步和禁用语义。
- 设备来源强制同校，非设备来源全学校权限。
- `(source_id, request_id) → command_id` 映射。
- 配置命令规范化、目标 offline 拒绝、15 秒超时。
- 配置 ACK、重复请求、幂等冲突和来源回程。
- route_service 重启后的配置命令安全恢复。
- 终态命令默认 30 天限量清理。

### 完成条件

- 权限、寻址、幂等、ACK、超时和恢复测试通过。
- 至少一个配置命令在授权集成环境完成端到端验证。
- 本里程碑文档与代码合入 `main`。

## 6. 里程碑四：飞控命令路由

### 前置条件

里程碑三已合入 `main`，从最新 `main` 重建工作树。

### 目标

在统一命令核心上接入飞控请求、进度、最终 ACK 和避免重复执行的恢复策略。

### 范围

- 来源侧 `control/request`、`control/ack` 协议。
- 设备侧 `control/set`、`control/ack` 对接。
- `in_progress`、`accepted`、`rejected`、`timeout` 映射。
- 默认 30 秒超时，进度 ACK 刷新期限。
- 原始设备 ACK JSONB 持久化。
- route_service 重启后不自动重发不确定飞控命令，标记 `delivery_uncertain`。
- 迟到 ACK 不反转已经返回来源的终态。

### 完成条件

- 飞控协议、状态机、超时、迟到 ACK 和恢复测试通过。
- 经授权完成至少一个无风险测试命令的端到端 ACK 验证。
- 本里程碑文档与代码合入 `main`。

### 前置条件

### 目标

### 范围

### 完成条件

- V1 综合验证记录合入 `main`。

## 8. 全局验收边界

V1 全部完成时必须满足：

- 每台设备只保存最新遥测，不保存逐帧历史。
- 实时状态事件与默认 5 秒数据库持久化异步分离。
- registration retained，telemetry 非 retained。
- 显式 offline 和默认 180 秒兜底离线生效。
- 设备来源同校，host_app/control_center 全学校。
- 配置和飞控命令共享幂等与 ACK 核心，但采用各自超时和恢复策略。
- 迁移版本化、幂等、可重复执行，测试不清空已有数据。
- 密码、证书私钥、真实配置和数据库数据目录未进入 Git。
- 所有文档、注释、日志、提交正文和回答使用中文。
