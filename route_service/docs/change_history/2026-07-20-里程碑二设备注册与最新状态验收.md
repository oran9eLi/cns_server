## 3. 非破坏性联调脚本

`tests/integration/里程碑二本机联调.sh` 必须显式接收测试配置、迁移目录、Broker 地址和端口。脚本完成：

- 两次执行迁移以验证幂等；
- retained online registration 在服务启动后的重放；
- `schools`、`devices`、`device_latest_states`、设备类型 `command_sources` 四表建档；
- 即时状态事件和默认 5 秒最新 telemetry 合并；
- 显式 offline、合法活动恢复和活动超时 offline；
- 未知设备 telemetry 不建档；
- 新订阅者收不到历史 telemetry，以验证非 retained 行为。

上述真实联调脚本不直接断言显式 offline 保留 `last_seen_at`、不足 5 秒停机强刷或队列满限频诊断；这三项的验收证据来自第 2 节自动化单元测试。

脚本使用随机 20 字符测试 `vendor_id` 和独立学校名。退出 trap 只定向删除引用该测试设备的命令、设备来源、最新状态和设备，并仅在学校已无设备时删除测试学校；同时只清除脚本创建的 retained registration。脚本不包含 `TRUNCATE`、`DROP DATABASE`、无条件 `DELETE` 或系统服务启停。

数据库断线 `degraded`、恢复补写及恢复后重新订阅 registration 需要可控数据库代理或独立数据库实例。通用脚本不会停止共享 PostgreSQL 来制造故障；本轮使用一次性临时实例单独完成了该项验证。

### 5.1 可复核执行证据

以下命令按实际执行过程脱敏整理。`<临时目录>`、`<测试配置>`、`<测试vendor>` 和 `<测试JSON>` 均为本轮一次性测试值，不包含密码或真实设备 payload。

环境版本检查：

```bash
psql --version
mosquitto_sub --help
pkg-config --modversion libpqxx libmosquitto
```

关键输出为 PostgreSQL `18.4`、Mosquitto `2.0.22`、libpqxx `7.10.0`、libmosquitto `2.0.22`。

临时依赖采用非特权进程，只监听本机高位端口：

```bash
/usr/lib/postgresql/18/bin/initdb \
  -D <临时目录>/pgdata --auth=trust --username=<临时测试用户> --no-locale
/usr/lib/postgresql/18/bin/pg_ctl -D <临时目录>/pgdata \
  -l <临时目录>/postgres.log \
  -o '-h 127.0.0.1 -p 25432 -k <临时目录>' start
createdb -h 127.0.0.1 -p 25432 -U <临时测试用户> <临时测试库>
mosquitto -p 28884
```

关键输出包含 `server started`，PostgreSQL 日志确认监听 `127.0.0.1:25432`，Mosquitto 日志确认为 `2.0.22` 并监听 `28884`。系统 `5432/1883` 服务未启停。

迁移与服务启动：

```bash
route_service/build-fresh-m2/route_service \
  --config <测试配置> --migrations route_service/migrations --migrate-only
route_service/build-fresh-m2/route_service \
  --config <测试配置> --migrations route_service/migrations --migrate-only
route_service/build-fresh-m2/route_service \
  --config <测试配置> --migrations route_service/migrations
```

首次迁移日志依次出现“已执行迁移版本 1”“已执行迁移版本 2”“数据库迁移完成”；第二次只出现“数据库迁移完成”，没有重复应用。正常模式出现“已连接 PostgreSQL”“路由服务已启动”“MQTT连接已恢复”。查询：

```sql
SELECT version, name FROM schema_migrations ORDER BY version;
```

返回版本 `1`、`2` 各一行。

MQTT 与 SQL 主链路使用以下模板：

```bash
mosquitto_sub -h 127.0.0.1 -p 28884 -q 0 \
  -t '<namespace>/events/devices/+/state'
mosquitto_pub -h 127.0.0.1 -p 28884 -q 2 -r \
  -t '<namespace>/<测试vendor>/registration' -m '<脱敏registration测试JSON>'
mosquitto_pub -h 127.0.0.1 -p 28884 -q 0 \
  -t '<namespace>/<测试vendor>/telemetry' -m '<脱敏telemetry测试JSON>'
```

四表 join 查询返回 `1`；状态事件依次观察到 `registration_online`、`telemetry`、`registration_offline`、恢复后的 `telemetry` 和 `activity_timeout`。连续发布序号 1、2 后等待 7 秒，`latest_telemetry` 查询只返回序号 `2`。显式离线查询返回 `offline`，新 telemetry 后返回 `online`，61 秒测试阈值后再次返回 `offline`。未知 vendor 的 `devices` 计数始终为 `0`。

非 retained 验证在发布完成后创建全新订阅者：

```bash
mosquitto_sub -h 127.0.0.1 -p 28884 -q 0 \
  -t '<namespace>/<测试vendor>/telemetry' -C 1 -W 2
```

命令以等待超时退出且无消息输出，证明新订阅者未收到旧 telemetry。

数据库故障注入只停启本轮专用临时集群：

```bash
/usr/lib/postgresql/18/bin/pg_ctl -D <临时目录>/pgdata stop -m fast
# 发布已登记设备 telemetry，并发布另一未知设备 retained registration。
/usr/lib/postgresql/18/bin/pg_ctl -D <临时目录>/pgdata \
  -l <临时目录>/postgres.log \
  -o '-h 127.0.0.1 -p 25432 -k <临时目录>' start
```

数据库停止后，先观察到即时 telemetry 事件；5 秒持久化尝试失败后观察到同一最新快照的 `degraded=true`。恢复后 SQL 查询确认故障期最后序号为 `42`，事件为 `change_reason=database_recovered`、`degraded=false`；故障期间未知设备的 retained registration 经重订阅后使设备计数从 `0` 变为 `1`。

有序退出与清理证据：

```bash
kill -TERM <route_service进程>
# 按测试vendor定向删除commands、command_sources、device_latest_states、devices；
# 仅在无设备引用时删除测试school，并用空 retained 消息清除测试registration。
/usr/lib/postgresql/18/bin/pg_ctl -D <临时目录>/pgdata stop -m fast
kill <临时Mosquitto进程>
```

SIGTERM 日志只包含“路由服务已启动”“路由服务已停止”，无 `ERROR`。清理后两个测试 vendor 的设备计数均为 `0`，测试学校无设备引用时计数为 `0`；临时 PostgreSQL/Mosquitto 均已停止，`<临时目录>` 已定向删除。

首次真实链路还发现显式 offline 后 telemetry 已使内存恢复 online，但数据库仍为 offline。根因是旧 `Mutation` 没有携带状态是否变化，`WriteFor` 对所有 telemetry 固定设置 `write_status=false`。先新增回归测试并确认红灯，再在 mutation 源头增加 `status_changed`，使恢复活动同时提交 telemetry 和 status；普通 online telemetry 仍只按批次写 telemetry。目标测试、全量测试和真实链路复验均通过。

真实 SIGTERM 退出曾固定记录“停止接收设备消息失败”。根因是生命周期层以空 handler 表达原子禁用，而 MQTT 适配层拒绝空 handler。新增回归测试确认红灯后，将空 handler 明确为停止接收语义；临时真实依赖上的 SIGTERM 冒烟复验只输出“路由服务已启动/已停止”，无 `ERROR`。
