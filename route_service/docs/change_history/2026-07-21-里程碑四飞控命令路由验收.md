# 里程碑四：飞控命令路由验收

日期：2026-07-21

## 验收范围

本次验收覆盖 route_service 的四种飞控命令协议、统一命令状态、PostgreSQL 持久化与恢复、MQTT QoS 2 路由、设备进度和终态 ACK、服务器超时以及非破坏性联调入口。现场服务器部署不属于本里程碑。

## 已通过

- 使用 GCC 15.2.0、libmosquitto 2.0.22、libpqxx 7.10.0 和 Debug 配置在全新 `build-m4-final` 目录完成配置与全量构建。
- 修复审查问题后重新执行全部 CTest，共 34 项，34 项通过、0 项失败，总耗时 2.44 秒。
- 静态协议测试覆盖 `set_motor_pwm`、`emergency_stop`、`takeoff`、`land`，对应 MAVLink 命令号为 31013、31090、31091、31092。
- 自动化测试覆盖配置与飞控共用来源幂等、目标寻址和权限，飞控下发及 ACK 使用 QoS 2、`retain=false`。
- 自动化测试覆盖 `in_progress` 重复持久化与期限刷新、设备 accepted/rejected/timeout、服务器 `control_timeout`、终态竞态和迟到 ACK 不反转。
- 自动化测试覆盖服务启动时先把飞控 `pending`、`dispatched`、`in_progress` 原子收敛为 `delivery_uncertain`，然后才启动 MQTT；恢复过程不重新发布飞控命令，配置恢复行为保持不变。
- 迁移 `004_修正命令活动与终态索引.sql` 只修正部分索引边界，静态检查确认未修改既有迁移、未清空或删除业务数据。
- `tests/integration/里程碑四飞控命令本机联调.sh` 通过 zsh 语法检查和 `--check-only`；检查模式未连接数据库或 Broker。脚本只清理当前 `source_id` 与随机 `m4-control-local-` 请求前缀匹配的命令，并对脚本新建设备执行引用安全清理。
- 差异审查发现飞控请求在入库前拒绝及幂等冲突时错误使用配置 ACK topic；已先补回归测试，再修正为按实际 `command_type` 回程。
- `git diff --check` 通过；安全检索未发现可执行的数据库清空、删除数据库、停止系统服务、批量杀进程或真实密码配置。

## 安全限制

- 本次没有向真实设备发送 `takeoff`、`land`、`emergency_stop` 或任何其他飞控命令。
- `emergency_stop` 当前只是普通飞控命令，不保证抢占 RPi 正在执行的事务；若 RPi 忙碌，仍可能返回 `command_busy`。
- 飞控命令一旦进入可能已送达设备的阶段，route_service 重启后不自动重发，而以 `delivery_uncertain` 表示结果不确定，优先避免重复动作。
- 验收脚本不会启动、停止或修改 PostgreSQL、Mosquitto、systemd、现场服务器或 RPi 配置，只连接用户明确提供的独立测试实例。
