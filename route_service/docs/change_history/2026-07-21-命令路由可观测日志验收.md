# 命令路由可观测日志验收记录

日期：2026-07-21

## 结论

命令路由与设备应答回程的两类 `INFO` 业务日志已完成代码实现和本机自动化验收。真实 PostgreSQL、Mosquitto、frpc 与树莓派配置命令链路尚未在本次改动后重新执行，因此保持待验证，不由自动化结果推定通过。

## 已通过

- `CommandService` 使用独立 `InformationSink` 生成业务日志，运行环境将其接入现有 `Logger::Info`；原有错误诊断仍使用独立错误回调。
- 配置命令在 MQTT 发布完成且数据库返回 `dispatched` 后才记录来源、固定顺序的实际变更字段和可信目标设备。
- 飞控命令记录 `set_motor_pwm`、`emergency_stop`、`takeoff` 或 `land`；仅 `set_motor_pwm` 附带四路 `pwm_us`。
- 设备 ACK 在相应状态成功持久化并调用来源 ACK 发布回调后记录；`in_progress` 与终态 ACK 分别记录。
- 设备显示使用 `学校名 / 设备内部编号（vendor_id）`，缺少学校或内部编号时分别使用“未知学校”和“未登记编号”。
- 幂等状态回放、MQTT 发布失败、非法 ACK 和无法关联 ACK 不记录成功业务日志。
- 成功业务日志不包含 `request_id`、`command_id`、原始 JSON 或完整 MQTT topic。
- 信息日志回调抛出异常时，ACK 仍回程，终态命令仍从活动集合移除。
- 多项配置字段按协议固定顺序使用中文逗号分隔；该项先通过失败测试复现空格分隔与设计不一致，再完成最小修复。
