日期：2026-07-28

仓库：`/home/hardware/cns_server`
部署提交：`e28dad2 merge: 合并 MQTT 设备当前快照发布`

## 1. 范围

本阶段把开发机上的 CNS 服务端运行环境迁移到硬件服务器，包含：

- PostgreSQL 数据库与现有业务数据；
- Mosquitto 演示 Broker；
- `route_service`；
- `backend_service`；
- React 前端静态文件；
- Nginx HTTP、REST 和 WebSocket 代理；
- 硬件服务器到公网 frps 的 MQTT TCP 透传；
- systemd 开机自启。

本阶段仍使用局域网匿名明文 MQTT `1883`，不代表里程碑五的正式 TLS、独立凭据和 ACL 已完成。

## 6. 服务验收

路由服务启动日志确认：

```text
已连接 PostgreSQL
路由服务已启动
MQTT连接已恢复
MQTT业务订阅已恢复
```

后端直连和 Nginx 代理的 `/api/health` 均返回：

```json
{
  "status": "ok",
  "dependencies": {
    "database": "ready",
    "mqtt": "ready"
  }
}
```

从开发机访问 `http://192.168.11.3/` 返回 HTTP 200。

真实 Mosquitto retained 验证通过：

- `cns_rpi/events/devices/online` 可立即取得完整在线目录；
- `cns_rpi/events/devices/{vendor_id}/state` 可立即取得完整设备当前快照；
- 全新客户端通过公网 `112.124.52.232:1883` 只订阅 MQTT，无需访问数据库或后端接口，即可立即取得上述 retained 数据；
- 排除 retained 消息后连续取得新的设备状态，消息为 QoS 1、`retain=false`，设备 `revision` 连续递增且 `change_reason=telemetry`；
- 当前真实遥测快照包含身份、设备资料、姿态、双电池、5G、LoRa、电机、Remote ID、系统状态、模块状态、告警和日志；
- 启动后近期 route_service 和 backend_service 日志未发现错误。

## 7. 树莓派公网接入补验

树莓派启动后确认其实际运行配置 `/var/lib/cns-rpi/config.json` 使用：

```text
host=112.124.52.232
port=1883
```

硬件服务器已有的 `frpc.service` 使用 `/etc/frp/frpc.toml`，代理关系为：

```text
112.124.52.232:1883
  → 云端 frps
  → 硬件服务器 frpc.service
  → 127.0.0.1:1883
  → Mosquitto
```

`frpc.service` 日志确认 `mqtt-tunnel` 为 `start proxy success`。树莓派无需重复改写或重启，启动后路由服务收到：

```text
设备上线：SEU/DCDW-001 vendor_id=DCDWCNS1S2MEAG1VTA0C
```

补验结果：

- Broker 收到真实设备 telemetry；
- `cns_rpi/events/devices/online` 包含该设备；
- PostgreSQL 中设备状态为 `online`，`telemetry_received_at` 持续更新；
- backend_service 设备详情接口返回最新遥测；
- 补验期间 route_service 和 backend_service 日志未发现错误。
