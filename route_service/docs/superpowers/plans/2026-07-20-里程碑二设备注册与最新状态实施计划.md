# Route Service 里程碑二：设备注册与最新状态实施计划

> **供智能体执行：** 必须按任务逐项使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`；步骤使用复选框跟踪，每个任务完成后先做规格审查，再做代码质量审查。

**目标：** 在现有 C++23 单体服务中完成 retained registration 设备发现、最新 telemetry、在线状态、异步 PostgreSQL 合并持久化和规范化状态事件。

**架构：** MQTT 回调只做有界复制，单业务线程独占全量内存设备目录，单 PostgreSQL 工作线程独占同步连接。低频关键状态立即写入，高频 telemetry 按设备只保留最后一份并默认每 5 秒刷新；数据库运行中断线时已有设备降级运行，新设备拒绝，恢复后补写并重新触发 retained registration。

**技术栈：** C++23、CMake 3.25+、GNU 工具链、libmosquitto 2.0.22、libpqxx 7.10.x、nlohmann/json、doctest、PostgreSQL、Mosquitto。

## 全局约束

- 文档、代码注释、运行日志、提交说明正文和回答使用中文；协议字段、C++ 标识符和日志等级保留英文。
- Git 提交使用 `<英文type>: <中文说明>`。
- 不修改 `cns_rpi`；设备端 QoS 0、`retain=false` 只做联调验证。
- 不保存逐帧历史；每台设备只保留最后一份完整 JSON object。
- 单条 payload 默认上限 262144 字节；时间使用服务器接收时间。
- JSON 时间为 UTC 毫秒 RFC 3339 `Z`，数据库时间为 `TIMESTAMPTZ`。
- 关键状态立即持久化；稳定 online telemetry 默认每 5 秒合并写入。
- PostgreSQL 冷启动不可用时退出；运行中不可用时每 5 秒重连，已有设备降级运行，新设备拒绝。
- 正常合并等待不算 degraded；只有数据库故障或故障内容尚未补写才算 degraded。
- 预计不新增 DDL；若必须增加索引，只能追加迁移，不能修改已发布迁移。
- 本机真实依赖测试只清理自身测试标识，不清空数据库。
- 现场服务器不可用时不得把本机验证写成现场已通过。
