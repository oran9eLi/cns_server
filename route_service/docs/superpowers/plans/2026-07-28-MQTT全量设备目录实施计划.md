# MQTT 全量设备目录实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 将 Route Service 的在线设备集合升级为全量设备目录，启动和 MQTT 重连时重发全部设备状态，并让仓库内 backend_service 接受删除 `school_id` 后的新 MQTT 协议。

**架构：** `DeviceRegistry` 提供按 `vendor_id` 排序的全部设备副本；`DeviceDirectory` 只维护影响目录发布的稳定字段，普通遥测不会触发全量目录。MQTT 外部桥发布 retained 全量目录和单设备完整状态，backend_service 只同步协议解析，不改变数据库和前端 API。

**技术栈：** C++23、nlohmann/json、doctest、CMake/CTest、TypeScript、Zod、Vitest、MQTT 3.1.1、Mosquitto 2.0.22。

## 全局约束

- 直接在 `main` 分支实施，不创建工作树，不使用子代理。
- 所有代码注释、测试名称、日志、文档和提交说明正文使用中文；Git 提交前缀使用英文。
- 新目录 topic 固定为 `{namespace}/events/devices/directory`，QoS 1、retained。
- 目录包含全部已入库设备，不包含 `school_id`，按 `vendor_id` 字典序排列。
- 单设备状态 MQTT JSON 删除 `school_id`，内部 `DeviceRecord.school_id` 和数据库结构保持不变。
- 启动和 MQTT 重连时重发全部设备状态，包括离线设备。
- 普通遥测不触发全量目录重发。
- 不执行数据库迁移，不清空任何数据，不在本地实现阶段修改硬件服务器状态。

- [ ] **步骤 4：实现外部桥全量目录发布**

普通遥测只改变 `latest_telemetry`、时间戳或设备 `revision` 时，目录项相等，因此不会重发全量目录。
