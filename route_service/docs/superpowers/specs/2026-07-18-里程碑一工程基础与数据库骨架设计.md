# Route Service 里程碑一：工程基础与数据库骨架设计

版本：2026-07-18

状态：已确认

## 1. 目标

本里程碑建立可构建、可测试、可配置的 C++23 `route_service` 工程骨架，并提供版本化 PostgreSQL 迁移能力。完成后，后续里程碑可以在稳定的配置、日志、并发、数据库和 MQTT 边界上增加设备注册、遥测与命令业务。

本里程碑面向当前单台现场服务器和不足 10 台设备，优先保证实现简单、边界清楚和可验证，不提前建设多实例、高可用、复杂依赖注入或多环境迁移一致性系统。

## 2. 范围

### 2.1 包含

- CMake 与 C++23 基础工程。
- `doctest` 单元测试入口。
- 严格 JSON 配置解析与命令行参数解析。
- 中文、单行、分级的标准输出日志。
- 通用线程安全有界队列。
- `libpqxx` PostgreSQL 最小适配层。
- `libmosquitto` MQTT 最小适配层与自动重连。
- 版本化、显式执行、只向前的数据库迁移。
- 五张核心业务表及迁移版本表的首版 DDL。
- 正常启动、迁移模式、信号退出的进程生命周期。
- 示例配置、本机单元测试和现场验证说明。

### 2.2 不包含

- 设备 registration、telemetry 或 ACK 的订阅与处理。
- MQTT 业务 topic 构造和消息路由。
- 设备在线状态机、遥测合并写库和实时状态事件。
- 配置命令或飞控命令业务。
- 命令清理任务的实际调度。
- systemd 单元、现场 PostgreSQL 安装、Mosquitto 配置修改。
- MQTT TLS、用户认证和 ACL 的现场启用。
- 自动数据库降级、多服务器迁移摘要校验和复杂连接池。

## 3. 工程结构

最终只生成一个部署和运行用的 `route_service` 可执行程序。CMake 内部按职责组织三个目标：

```text
route_core
  配置、日志、有界队列、迁移规划等纯逻辑

route_adapters
  PostgreSQL 与 MQTT 的薄封装

route_service
  命令行、启动顺序、信号和生命周期编排
```

建议目录如下：

```text
route_service/
├── CMakeLists.txt
├── config/
│   └── route_service.example.json
├── migrations/
│   ├── 001_创建迁移版本表.sql
│   └── 002_创建核心业务表.sql
├── src/
│   ├── core/
│   │   ├── config/
│   │   ├── logging/
│   │   ├── queue/
│   │   └── migration/
│   ├── adapters/
│   │   ├── postgres/
│   │   └── mqtt/
│   └── main.cpp
└── tests/
```

`route_core` 不依赖正在运行的 PostgreSQL 或 Mosquitto。`route_adapters` 隔离第三方库的资源生命周期和错误转换，不承载设备或命令业务。`main.cpp` 只负责启动与停止编排，不堆放配置解析、SQL 或 MQTT 回调细节。

不建立通用插件系统，也不为每个类创建模拟接口。只有外部资源边界需要隔离。

## 4. 依赖与构建

本机和现场服务器均通过 Ubuntu 系统包安装完整开发依赖。CMake 必须找到：

- 支持 C++23 的编译器与 CMake；
- `libmosquitto`；
- `libpqxx`；
- `nlohmann/json`；
- `doctest`。

缺少任何依赖时，CMake 配置直接失败并输出中文说明。不使用 CMake `FetchContent` 或其他方式自动联网下载依赖，也不提供“缺少数据库或 MQTT 库时只构建部分目标”的降级路径。

编译启用严格警告；具体警告参数和是否将警告视为错误由实施计划结合本机、服务器编译器版本确定，不能以降低警告等级掩盖问题。

## 5. 命令行与运行模式

### 5.1 命令行

正常运行和迁移模式都必须显式提供配置文件与迁移目录：

```bash
route_service \
  --config /明确路径/route_service.json \
  --migrations /明确路径/migrations
```

支持以下参数：

- `--config <路径>`：必填 JSON 配置文件。
- `--migrations <目录>`：必填迁移 SQL 目录。
- `--migrate-only`：执行迁移后退出，不启动 MQTT。
- `--help`：显示中文帮助并成功退出。
- `--version`：显示程序版本并成功退出。

不设置默认配置路径，不搜索当前工作目录，不根据可执行文件位置推导迁移目录。未知参数、重复冲突参数或缺少必需值时，输出中文错误并以非零状态退出。

### 5.2 正常模式

启动顺序为：

```text
解析命令行
→ 读取并严格校验配置
→ 创建日志器
→ 连接 PostgreSQL
→ 检查迁移版本
→ 启动 MQTT 网络循环与自动重连
→ 等待 SIGINT 或 SIGTERM
→ 停止 MQTT 并有序退出
```

数据库连接失败、存在未执行迁移或数据库包含程序不认识的新迁移版本时，启动失败。第一里程碑不在正常启动中自动修改数据库。

MQTT 首次连接失败时进程保持运行，由 `libmosquitto` 按配置自动重连，并以限频警告反映持续故障。本里程碑不订阅 topic；连接成功后仅维持客户端生命周期。

信号处理函数只设置退出标志，不执行日志、内存分配、数据库或 MQTT 操作。主线程观察退出标志后完成有序停止。

### 5.3 迁移模式

`--migrate-only` 的顺序为：

```text
解析命令行和配置
→ 创建日志器
→ 连接 PostgreSQL
→ 扫描并校验迁移文件
→ 在事务中依次执行未应用迁移
→ 成功后退出
```

迁移模式不初始化 MQTT。任一迁移失败时回滚当前迁移、输出中文错误并返回非零退出码。

## 6. JSON 配置

第一里程碑只定义实际需要的四部分配置：

```json
{
  "database": {
    "host": "127.0.0.1",
    "port": 5432,
    "name": "cns",
    "user": "cns_route",
    "password": "请替换为现场随机强密码",
    "connect_timeout_seconds": 5
  },
  "mqtt": {
    "host": "127.0.0.1",
    "port": 1883,
    "keepalive_seconds": 60,
    "client_id": "cns-route-service",
    "username": "",
    "password": "",
    "reconnect_delay_seconds": 1,
    "reconnect_delay_max_seconds": 30
  },
  "logging": {
    "level": "info"
  },
  "queues": {
    "mqtt_inbound_capacity": 256
  }
}
```

上述数值是示例初值，实施计划必须为端口、超时、keepalive、重连关系和队列容量定义合理范围并编写边界测试。

配置采用严格模式：

- 未知字段、缺失字段、错误类型、必填标识或数据库密码为空，以及数值越界均拒绝启动。
- 错误信息包含完整 JSON 字段路径。
- `reconnect_delay_seconds` 不得大于 `reconnect_delay_max_seconds`。
- MQTT 用户名和密码为空表示使用当前匿名 1883 Broker；支持字段不表示本里程碑启用现场认证。
- 数据库使用专用账号和随机强密码，不使用 Linux 服务账户身份认证。

仓库只提交不含真实凭据的示例配置，数据库密码使用明确的替换提示值。现场 PostgreSQL 初始化时生成真实密码，保存到现场专用 JSON 配置；该文件不进入 Git，并设置为专用服务账户所有、权限 `0600`。

后续里程碑新增离线阈值、遥测刷新、命令超时、固定来源和清理周期时，必须同时更新配置实现、示例、测试和相关设计文档，不在本里程碑提前定义。

## 7. 日志

route_service 只写标准输出和标准错误，由现场 systemd/journald 负责保存与轮转。程序不写自身日志文件，也不实现文件轮转。

格式为：

```text
[2026-07-18 14:30:25.123] [INFO ] 中文消息
```

规则如下：

- 时间使用服务器本地时区，格式为 `YYYY-MM-DD HH:MM:SS.mmm`。
- 系统时间异常时沿用树莓派日志的固定宽度无效时间占位符。
- 日志等级保持英文固定宽度：`DEBUG`、`INFO `、`WARN `、`ERROR`。
- 服务器日志不包含树莓派现有的 `+000123.456s` 程序运行时间段；树莓派格式不修改。
- `DEBUG`、`INFO` 写 stdout，`WARN`、`ERROR` 写 stderr。
- 消息使用中文，协议字段、错误码和技术标识符保留英文。
- CR/LF 转为空格，确保一条记录只占一行。
- 密码不得输出；外部 payload 只允许记录安全、截断后的上下文。
- 日志器线程安全，保证多线程日志不会交叉拼接。

配置级别只接受 `debug`、`info`、`warn` 和 `error`。

## 8. 有界队列

第一里程碑实现一个通用线程安全有界队列，供后续 MQTT 回调线程向业务线程交付消息。

语义为：

- 容量在创建时由配置确定，创建后固定且必须大于零。
- 生产者通过非阻塞 `TryPush()` 入队。
- 队列已满或已关闭时立即返回失败，不阻塞 MQTT 回调线程。
- 消费者可以阻塞等待消息。
- 关闭队列后唤醒所有等待中的消费者。
- 队列关闭后不再接受新元素；消费者继续按 FIFO 取完关闭前已经入队的元素，队列变空后返回“已关闭”。

本里程碑只验证容量、FIFO、满队列、关闭唤醒和并发行为。队列满时丢弃哪类 MQTT 消息、如何限频记录错误，留到实际接入业务的后续里程碑决定。

## 9. PostgreSQL 迁移

### 9.1 基本规则

迁移 SQL 位于仓库 `route_service/migrations/`，文件名使用三位递增版本号和中文说明，例如：

```text
001_创建迁移版本表.sql
002_创建核心业务表.sql
```

迁移程序按版本号排序，拒绝重复版本、无法识别的文件名和版本缺口。迁移版本表记录：

- `version`：迁移版本主键；
- `name`：迁移名称；
- `applied_at`：服务器执行时间。

当前只有一台服务器，不记录 SQL 文件 SHA-256 摘要。已发布迁移仍不得修改；需要修正时必须追加新迁移，Git 历史负责追踪文件变化。

每个迁移在独立 PostgreSQL 事务中执行。SQL 全部成功后才写入对应版本记录；失败时回滚当前迁移。重复执行 `--migrate-only` 时跳过已经记录的版本，不清空或覆盖业务数据。

迁移采用只向前策略，不提供自动 `down` SQL。结构变更前根据风险建立 PostgreSQL 备份或其他明确恢复点；失败后恢复备份，或修复问题并追加迁移。

### 9.2 正常启动检查

正常模式只比较迁移目录和数据库版本：

- 两者一致时继续启动。
- 数据库尚无 `schema_migrations` 表时，视为全部迁移均未执行，而不是报告普通 SQL 查询错误。
- 目录中存在数据库未执行版本时，报错并要求显式运行 `--migrate-only`。
- 数据库包含当前程序不认识的版本时，报错退出，防止旧程序操作新结构。

## 10. 首版数据库结构

所有时间列使用 `TIMESTAMPTZ`。状态列使用 `TEXT` 配合 `CHECK`，不创建 PostgreSQL `ENUM`。核心外键使用默认 `NO ACTION`，不设置 `ON DELETE CASCADE`。

### 10.1 schema_migrations

| 字段 | 类型 | 约束 |
|---|---|---|
| `version` | INTEGER | 主键，正整数 |
| `name` | TEXT | 非空 |
| `applied_at` | TIMESTAMPTZ | 非空，默认当前时间 |

### 10.2 schools

| 字段 | 类型 | 约束 |
|---|---|---|
| `school_id` | BIGSERIAL | 主键 |
| `school_name` | TEXT | 唯一、非空 |
| `created_at` | TIMESTAMPTZ | 非空，默认当前时间 |

### 10.3 devices

| 字段 | 类型 | 约束 |
|---|---|---|
| `vendor_id` | VARCHAR(20) | 主键 |
| `school_id` | BIGINT | 非空，外键到 `schools` |
| `dcdw_label` | TEXT | 可空 |
| `model_version` | TEXT | 非空，默认 `CNS v1.0` |
| `provisioned_at` | TIMESTAMPTZ | 非空，默认当前时间 |

额外约束为 `UNIQUE(school_id, dcdw_label)`。PostgreSQL 允许该约束中多行 `dcdw_label=NULL` 共存。

### 10.4 device_latest_states

| 字段 | 类型 | 约束 |
|---|---|---|
| `vendor_id` | VARCHAR(20) | 主键，外键到 `devices` |
| `status` | TEXT | 非空，只允许 `online`、`offline` |
| `last_seen_at` | TIMESTAMPTZ | 可空 |
| `latest_telemetry` | JSONB | 可空 |
| `telemetry_received_at` | TIMESTAMPTZ | 可空 |
| `updated_at` | TIMESTAMPTZ | 非空，默认当前时间 |

### 10.5 command_sources

| 字段 | 类型 | 约束 |
|---|---|---|
| `source_id` | VARCHAR(64) | 主键，匹配 `[A-Za-z0-9._-]+` |
| `source_kind` | TEXT | 非空，只允许 `device`、`host_app`、`control_center` |
| `device_vendor_id` | VARCHAR(20) | 可空，外键到 `devices`，且唯一 |
| `enabled` | BOOLEAN | 非空，默认 `true` |
| `created_at` | TIMESTAMPTZ | 非空，默认当前时间 |
| `updated_at` | TIMESTAMPTZ | 非空，默认当前时间 |

检查约束保证：

- `source_kind='device'` 时 `device_vendor_id` 非空且 `source_id=device_vendor_id`。
- 其他来源的 `device_vendor_id` 必须为空。

不建立 `source_school_permissions`。

### 10.6 commands

| 字段 | 类型 | 约束 |
|---|---|---|
| `command_id` | UUID | 主键，由 route_service 生成 UUID v4 |
| `source_id` | VARCHAR(64) | 非空，外键到 `command_sources` |
| `request_id` | VARCHAR(128) | 非空 |
| `command_type` | TEXT | 非空，只允许 `config`、`control` |
| `target_vendor_id` | VARCHAR(20) | 可空，外键到 `devices` |
| `request_payload` | JSONB | 非空 |
| `status` | TEXT | 非空，受生命周期检查约束 |
| `error_code` | TEXT | 可空 |
| `error_message` | TEXT | 可空 |
| `device_ack` | JSONB | 可空 |
| `created_at` | TIMESTAMPTZ | 非空，默认当前时间 |
| `dispatched_at` | TIMESTAMPTZ | 可空 |
| `updated_at` | TIMESTAMPTZ | 非空，默认当前时间 |
| `completed_at` | TIMESTAMPTZ | 可空 |

命令状态只允许：

```text
pending、dispatched、in_progress、succeeded、failed、timeout、delivery_uncertain
```

`UNIQUE(source_id, request_id)` 保存来源幂等关系。`target_vendor_id` 允许为空，因为具有合法幂等键但在寻址前被拒绝的请求也需要保存终态结果。后续命令里程碑负责细化状态与时间字段的一致性检查，不在数据库骨架中编写会妨碍尚未实现状态流转的复杂约束。

### 10.7 删除与清理

V1 不提供物理删除学校、设备或来源的业务。设备和来源不再使用时保留记录并改变状态或设为禁用。外键不级联删除，避免误删学校时连带清空设备和命令。

终态命令默认保留 30 天后限量批次清理，但清理任务在后续命令里程碑实现。非终态命令不得清理。

## 11. 外部适配层

### 11.1 PostgreSQL

PostgreSQL 适配层使用 `libpqxx` 同步连接与事务，负责：

- 建立专用连接；
- 读取数据库迁移版本；
- 执行单个迁移事务；
- 把 `libpqxx` 异常转换为带上下文的中文错误。

第一里程碑不实现连接池。正常启动只需完成迁移版本检查；迁移模式串行执行 SQL。

### 11.2 MQTT

MQTT 适配层使用 `libmosquitto`，负责：

- 库生命周期；
- 客户端创建和销毁；
- 可选用户名密码设置；
- 异步连接、网络循环和指数重连参数；
- 连接状态日志；
- 有序停止。

首次连接失败和运行中断线都不终止进程。重复失败日志必须限频，避免 Broker 长时间不可用时淹没 journald。本里程碑不订阅、不发布、不解析 JSON。

## 12. 错误处理

- 命令行错误：中文说明用法，非零退出。
- 配置读取或校验失败：指出文件和字段路径，非零退出。
- 日志初始化失败：写 stderr 后退出。
- PostgreSQL 连接失败：正常模式和迁移模式均退出。
- 迁移目录非法：迁移和正常模式均退出。
- 待执行迁移：正常模式退出，迁移模式执行。
- 未知数据库迁移版本：两种模式都退出，不尝试降级。
- 单个迁移失败：回滚该迁移并退出，之前已提交版本保持不变。
- MQTT 不可用：保持进程运行并自动重连。
- 信号退出：不在信号处理函数内调用非异步信号安全操作。

所有错误日志不得包含数据库密码、MQTT 密码或完整连接串。

## 13. 测试与验证

### 13.1 本机自动化测试

不依赖正在运行的数据库和 Broker 的测试覆盖：

- 命令行的正常、缺失、未知和冲突参数。
- JSON 配置成功解析、未知字段、缺失字段、类型错误和数值边界。
- 敏感配置不出现在错误文本和日志中。
- 日志时间、英文等级、中文消息、单行清理、级别过滤和 stdout/stderr 分流。
- 有界队列的 FIFO、容量、满队列、关闭、唤醒和并发行为。
- 迁移文件名解析、排序、重复版本、版本缺口和迁移规划。
- 数据库版本一致、待迁移和未知新版本的纯逻辑判断。
- SQL 文件的静态契约检查，包括表、主键、外键、唯一约束、`CHECK` 和禁止级联删除。

本机安装完整编译依赖，执行 CMake 配置、构建和 `ctest`。纯逻辑测试不要求本机启动 PostgreSQL 或 Mosquitto。

### 13.2 现场验证

现场状态变更必须在实施计划确认且用户另行授权后执行。获授权后验证：

- 安装缺失的 PostgreSQL 与 C++ 开发依赖。
- 创建专用数据库、账号和随机强密码。
- 首次迁移成功并生成所有表。
- 重复运行 `--migrate-only` 不重复执行、不破坏已有数据。
- 正常模式在迁移一致时启动。
- 存在待执行迁移时正常模式拒绝启动。
- 连接当前匿名 Mosquitto 1883，断开和恢复时自动重连。
- `SIGTERM` 后有序退出。

验证使用独立标识，不删除、清空或覆盖服务器已有数据。未获授权或未完成的现场项目必须明确记录为“未验证”，不能写成已通过。
