# 收尾里程碑：展示链路固化设计

版本：2026-07-22

状态：待用户审阅确认

## 1. 背景

`route_service` 已完成设备注册与最新状态、固定来源与配置命令、飞控命令路由、命令可观测日志、本机 systemd 服务、后端接入和前端展示链路联调。由于硬件服务器暂不可用，当前展示链路临时落在本机：

```text
树莓派
  → 云服务器 frps TCP 透传
  → 本机 frpc
  → 本机 Mosquitto 18884
  → 本机 route_service
  → 本机 PostgreSQL
  → backend_service
  → Nginx 托管前端或前端开发服务
```

本里程碑的目标不是扩大功能边界，而是把当前可展示链路收口到可重启、可追踪、可复现，并修复已发现的两个服务端可靠性问题。

## 2. 目标

- 固化当前本机展示链路的部署边界、配置路径、启动方式和日志追踪方式。
- 确认 `route_service` 在 Broker 晚启动或 Broker 重启后，无需重启服务即可恢复业务订阅和设备在线状态。
- 修复配置命令中“数据库命令状态转换失败”的误报和状态收敛缺口。
- 保持配置命令和飞控命令现有协议、幂等、ACK 回程、日志格式和数据库表结构的整体方向不变。
- 补齐收尾验收项，保证后续演示和移交时有明确检查清单。
- 同步相关文档，避免关键部署、恢复和验收规则只停留在对话中。

## 3. 非目标

- 不实现正式 MQTT TLS、ACL、每设备凭据、8883 端口和证书自动化。
- 不改造云服务器 frps 安全策略，不引入域名，不切换到正式现场服务器。
- 不修改树莓派协议，不改变 registration retained、telemetry 非 retained、配置 ACK 或飞控 ACK 的既有语义。
- 不新增遥测历史存储、批量压力测试、多实例高可用或复杂过载保护。
- 不新增数据库业务表；除非修复必须，否则不新增迁移。
- 不调整 backend_service 鉴权模型、账号权限或前端交互体验。
- 不把“前端命令失败后醒目显示具体失败原因”纳入本阶段。该项属于用户体验和前后端展示细节，后续单独设计和修改。

## 4. 当前链路基线

### 4.1 本机服务

当前展示环境使用本机作为临时服务器：

- `mosquitto-18884.service`：本机 Mosquitto 独立实例，监听 `18884`，允许匿名明文连接。
- `cns-frpc.service`：把云服务器公网入口转发到本机 `127.0.0.1:18884`。
- `cns-route-service.service`：本机 route_service systemd 服务，连接本机 Broker 和 PostgreSQL。
- `cns-backend-service.service`：本机 backend_service systemd 服务。
- Nginx 或前端开发服务：提供浏览器页面。

该链路只用于当前演示和开发验证。匿名明文 MQTT 不作为最终生产安全方案。

### 4.2 数据与权限

`route_service` 仍是以下表的唯一写入者：

- `schools`
- `devices`
- `device_latest_states`
- `command_sources`
- `commands`

`backend_service` 只读设备数据，并通过固定来源 `web-console` 向 route_service 提交命令。Web 用户级权限暂不由 route_service 处理。

### 4.3 命令链路

配置命令和飞控命令均走同一类链路：

```text
固定来源 request
  → route_service 来源校验、幂等、寻址、在线检查
  → commands 表持久化
  → MQTT QoS 2 发布到目标设备
  → 设备 ACK
  → commands 表状态更新
  → 来源 ack topic
  → backend_service WebSocket
  → 前端页面
```

本里程碑只修复 route_service 在该链路中的恢复和状态收敛问题，不改变对外 topic 和 payload 主结构。

## 5. 问题一：Broker 晚启动后的业务订阅恢复

### 5.1 现象

曾出现以下情况：

1. route_service、backend_service 和前端先启动。
2. Broker 未运行，页面显示设备离线。
3. 后续启动 Broker，route_service 日志显示 MQTT 已连接。
4. 设备在线状态长时间未恢复。
5. 重启 route_service 后，设备在线状态恢复。

### 5.2 原因判断

该现象更像 route_service 的 MQTT 恢复链路缺口，而不是数据库问题或设备端问题。

当前“MQTT 连接恢复”和“业务订阅恢复”没有形成足够明确的状态边界。连接成功后如果业务订阅失败，服务可能只记录泛化错误，缺少后续补订阅机制；而 retained registration 的重新获取依赖订阅成功。如果 route_service 没有成功订阅 registration topic，就不会收到 Broker 中已有的 retained online/offline 状态。

重启 route_service 后能恢复，说明 Broker 内很可能已有 retained registration，问题集中在服务端重连后订阅与 retained 状态重放不可靠。

### 5.3 设计

收尾里程碑中将 MQTT 恢复拆成两个明确阶段：

```text
MQTT TCP/协议连接恢复
  → 业务 topic 订阅恢复
  → retained registration 被重新接收
  → 设备在线状态恢复
```

具体规则：

- `MQTT连接已恢复` 只表示客户端连接 Broker 成功。
- 只有 registration、telemetry、配置请求、配置 ACK、飞控请求、飞控 ACK 等业务订阅全部成功后，才记录 `MQTT业务订阅已恢复`。
- 每个订阅失败必须记录具体阶段，不能只输出泛化的“订阅失败”。
- 连接已恢复但订阅未完全成功时，route_service 必须周期性重试业务订阅。
- registration 订阅成功后，必须依赖 Broker retained 消息重新进入现有注册处理链路，不能通过伪造设备在线状态绕过协议。
- 重复收到 retained registration 时，仍按现有幂等注册逻辑处理，不新增特殊表。

### 5.4 验收

该问题的验收以可复现流程为准：

1. 停止 Broker。
2. 启动或保持 route_service 运行。
3. 启动 Broker。
4. 树莓派连接 Broker 并发布 retained registration，或 Broker 中已有 retained registration。
5. 不重启 route_service。
6. route_service 日志能看到连接恢复、业务订阅恢复。
7. 数据库和前端能恢复设备在线状态。

验收不能以“重启 route_service 后恢复”作为通过标准。

## 6. 问题二：命令状态转换失败误报与状态收敛

### 6.1 现象

配置命令测试中曾出现：

```text
[ERROR] 命令数据库操作失败：数据库命令状态转换失败
```

同一时间段内，设备 ACK 仍然成功返回并转发给来源，后续命令也能继续执行。飞控命令未复现相同问题。

### 6.2 原因判断

该问题更像代码状态机的异步竞态收敛缺口，不像 PostgreSQL 偶发 IO 故障。

现有 PostgreSQL 层能够区分：

- 状态迁移非法。
- 状态已变化。
- SQL 或连接异常。

但运行时适配层把具体失败原因压缩成了统一的“数据库命令状态转换失败”。命令服务收到该结果后直接按错误日志处理，没有重新读取当前命令状态判断是否已经被另一路径推进到期望状态或更晚状态。

配置命令链路里，QoS 发布完成、设备 ACK、早到 ACK 暂存、超时扫描和恢复逻辑都可能在很短时间内交错。对这种条件更新失败，不能直接等同为数据库不可用。

### 6.3 设计

收尾里程碑中将数据库状态转换结果分成三类处理：

| 类型 | 含义 | 处理 |
|---|---|---|
| 数据库不可用 | 连接失败、事务失败、SQL 异常 | 记录 ERROR，按现有数据库恢复机制处理 |
| 状态已变化 | 条件更新未命中，当前状态可能已被其他路径推进 | 重新读取命令当前状态并收敛 |
| 状态迁移非法 | 代码请求了不允许的状态转换 | 记录 ERROR，并保留足够上下文用于修复 |

收敛规则：

- 如果重新读取后发现命令已经处于期望状态，按成功处理，不再输出 ERROR。
- 如果重新读取后发现命令已处于更晚终态，保持现有终态，不反转状态，不重复发送终态 ACK。
- 如果当前状态仍可合法推进，则按当前状态重新尝试一次受控转换。
- 如果当前状态与请求不兼容，但属于迟到 ACK、重复发布完成或超时后的迟到事件，记录诊断日志，不按数据库故障处理。
- 只有无法解释的数据不一致、非法状态迁移或真实数据库异常才输出 ERROR。

该设计保持既有核心原则：

- `commands` 表仍是命令状态的权威来源。
- 状态转换仍通过“期望旧状态 + 目标新状态”的条件更新控制竞态。
- 命令终态不可反转。
- 来源 ACK 不得因重复事件被重复发布。

### 6.4 验收

自动化测试至少覆盖：

- 发布完成和设备 ACK 接近同时到达时，不误报数据库错误。
- 设备 ACK 早于发布完成时，仍能在 `dispatched` 后推进到终态。
- 重复发布完成 MID、重复设备 ACK、迟到 ACK 不反转终态。
- 超时后迟到 ACK 不把 `timeout` 改回 `succeeded`。
- 真正数据库不可用时仍输出错误并进入既有恢复路径。

真实链路验收至少覆盖：

- 配置命令多次连续下发，不出现“数据库命令状态转换失败”的误报。
- 飞控命令正常成功或返回设备拒绝时，状态和 ACK 回程不受影响。

## 7. 日志收口

本里程碑不改变已经确认的日志格式：

```text
[2026-07-22 09:04:09.394] [INFO ] 中文单行消息
```

需要补齐的日志规则：

- MQTT 连接恢复、业务订阅恢复、订阅失败阶段必须可区分。
- 命令状态转换中，真实数据库故障与良性竞态收敛不得混用同一 ERROR 文案。
- 正常命令业务日志继续只显示来源、命令、学校、设备号和目标，不显示 `request_id`、`command_id` 或完整 topic。
- 配置命令和飞控命令成功路由、设备应答回程日志保持现有中文表达。

日志只用于运维观察，不作为业务状态的唯一依据。业务状态仍以数据库和来源 ACK 为准。

## 8. 部署文档收口

本里程碑需要把当前临时展示部署写清楚：

- 本机 PostgreSQL 数据库、账号、迁移执行方式和注意事项。
- `mosquitto-18884.service` 的用途、配置路径、持久化目录、AppArmor 本地规则和 journal 查看命令。
- `cns-frpc.service` 的作用和启停方式；真实云服务器地址和密钥类配置不得提交。
- `cns-route-service.service` 的配置路径、服务用户、重启方式和日志查看方式。
- `cns-backend-service.service` 的配置路径、监听端口和日志查看方式。
- Nginx 托管前端的构建目录、站点配置原则和常见 404/500 原因。

部署文档必须明确区分：

- 当前展示链路：本机 Broker、匿名明文、frp 透传。
- 最终安全链路：现场 Mosquitto、TLS/ACL、独立凭据、受控端口。

不能把当前展示链路描述为最终安全部署。

## 9. 验收边界

收尾里程碑完成后，至少应能执行以下检查：

1. 重启本机后，`mosquitto-18884`、`frpc`、`route_service`、`backend_service` 能自动恢复。
2. route_service 启动早于 Broker 时，Broker 恢复后业务订阅和设备在线状态能自动恢复。
3. 树莓派通过公网入口连接本机 Broker 后，registration、online/offline 和 telemetry 能进入数据库和前端。
4. Web 或 MQTT 固定来源下发配置命令，route_service 能路由到目标设备并回传 ACK。
5. Web 或 MQTT 固定来源下发飞控命令，route_service 能路由到目标设备并回传 ACK。
6. 配置命令连续下发时，不再出现良性竞态导致的“数据库命令状态转换失败”误报。
7. 服务日志能清楚看到“来自谁、什么命令、发给哪个学校/设备、收到哪个设备应答、回给谁”。
8. 数据库迁移可重复检查，不清空、不破坏已有设备和命令数据。

如果现场硬件服务器仍不可用，本里程碑验收只声明“本机展示链路通过”，不得写成“现场服务器通过”。

## 10. 文档同步范围

设计确认并实施后，需要同步：

- `route_service/README.md`：补充收尾后的本机展示链路、启动、日志和验收入口。
- `route_service/docs/2026-07-18-路由服务V1设计.md`：更新实施进度和已知恢复规则。
- `route_service/docs/2026-07-18-路由服务V1实施计划.md`：更新当前里程碑状态或追加收尾说明。
- `route_service/docs/change_history/`：新增收尾里程碑验收记录。
- 桌面部署说明：如仍作为现场操作入口，需同步当前最终命令和注意事项。

后端和前端失败原因展示不在本阶段同步，只在后续用户体验改动时另行设计。

## 11. 风险与回退

- MQTT 恢复修复可能影响现有重连订阅路径，必须用单元测试和本机 Broker 流程验证。
- 命令状态收敛修复可能影响配置和飞控两类命令，必须覆盖两类命令的状态机测试。
- 如果不新增数据库字段，回退只需要恢复 route_service 可执行文件；数据库结构不变。
- 如果实施中发现必须新增迁移，必须先更新实施计划并说明迁移内容、重复执行行为和回退方式。
- 本机 systemd 服务替换可通过重新安装上一版可执行文件并重启服务回退。

## 12. 延期项

- MQTT TLS、ACL、每设备凭据、8883 和正式证书部署。
- 云服务器 frps 安全加固和固定域名接入。
- 硬件服务器 PostgreSQL、Mosquitto、systemd 和 Nginx 正式迁移。
- 多设备压力测试和更细粒度过载保护。
- 遥测历史存储。
- Web 用户鉴权与学校级权限。
- 前端命令失败原因的醒目展示、设备 ACK 细节展示和用户体验优化。
