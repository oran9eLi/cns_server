# MQTT 公网安全接入与 FRP 部署设计

日期：2026-07-21
状态：待书面审阅确认

## 1. 目标与范围

本设计为 Route Service V1 里程碑五确定最终 MQTT 公网接入方案。在现场硬件服务器暂不可用期间，开发机临时承担现场服务器角色；硬件服务器恢复后，按相同边界迁移 Mosquitto、frpc、route_service 和 PostgreSQL。

目标如下：

- 树莓派通过云服务器弹性公网 IP 接入最终 MQTT 入口。
- MQTT 从客户端到现场 Mosquitto 全程使用 TLS，不在云服务器终止 TLS。
- 使用每设备独立用户名和密码，并通过 Mosquitto ACL 限制 topic。
- route_service、backend_service 和人工联调来源使用彼此独立的服务账户。
- frp 控制链路同时使用 TLS 和文件 token，只开放 MQTT 所需端口。
- 密码、token、证书私钥和真实现场配置不进入 Git。

本设计不实现集中凭据管理平台、多 Broker 高可用、自动证书签发、客户端证书双向认证或无停机双链路迁移。当前设备不足十台，V1 采用逐台人工配置和轮换。

## 2. 部署边界

最终数据路径为：

```text
树莓派 / backend_service / 管理客户端
        │ MQTT TLS + 用户名密码
        ▼
云服务器弹性公网IP:8883
        │ frps TCP原样转发，不终止MQTT TLS
        │ frp控制链路使用TLS + token
        ▼
现场服务器frpc
        │ 127.0.0.1:8883
        ▼
Mosquitto TLS + ACL
        ├── route_service
        └── PostgreSQL
```

云服务器只运行 frps。Mosquitto、frpc、route_service 和 PostgreSQL 最终均运行在唯一一台现场硬件服务器。当前开发机仅临时替代现场服务器，不改变最终部署边界。

公网和本地 MQTT TLS 端口统一为 TCP `8883`。Mosquitto 正式 listener 只绑定 `127.0.0.1:8883`，由本机 route_service 和 frpc 访问，不直接暴露到现场局域网。云服务器防火墙只开放 frps 控制端口和 TCP `8883`。

## 3. 信任模型与证书

### 3.1 私有 CA

建立 CNS 私有根 CA：

- 根 CA 有效期 10 年。
- 根 CA 私钥使用强口令加密并离线保存，不存放在 Broker、云服务器、树莓派或 Git 仓库。
- 当前只有一个 Broker，不引入中间 CA。
- Broker 和 frps 分别使用独立叶证书和私钥，不得复用。

### 3.2 Mosquitto 证书

Broker 证书有效期 1 年，SAN 至少包含：

- 云服务器弹性公网 IP，供树莓派及公网客户端验证；
- `127.0.0.1`，供本机 route_service 验证。

树莓派把 MQTT host 配置为弹性公网 IP；route_service 把 MQTT host 配置为 `127.0.0.1`。客户端必须同时验证证书链和目标 IP，不提供跳过校验的配置开关。

### 3.3 frps 证书

frps 使用同一 CNS 根 CA 签发的独立服务端证书，SAN 包含弹性公网 IP。frpc 必须配置 CNS 根 CA 并严格校验 frps 身份。

### 3.4 生命周期

- TLS 最低版本为 TLS 1.2，支持时由系统库优先协商 TLS 1.3。
- 叶证书到期前 30 天开始轮换。
- 使用同一根 CA 续签叶证书时，客户端无需更换根证书。
- 弹性公网 IP 解绑或更换后，必须重新签发包含新 IP 的叶证书后才能切换。

## 4. Mosquitto 认证与 ACL

Mosquitto 正式配置必须：

- 设置 `allow_anonymous false`；
- 使用独立 `password_file` 和 `acl_file`；
- 加载 CNS 根 CA、Broker 证书和 Broker 私钥；
- 仅监听回环地址的 TLS `8883`；
- 不保留可从公网或局域网访问的匿名 listener。

### 4.1 设备账户

每台树莓派使用独立账户：

- 用户名等于设备 `vendor_id`；
- 密码为逐设备生成的随机强密码；
- 单台设备泄露时只撤销该设备凭据。

设备 ACL 使用 Mosquitto `%u` 用户名替换，只允许写入：

```text
cns_rpi/%u/registration
cns_rpi/%u/telemetry
cns_rpi/%u/config/ack
cns_rpi/%u/control/ack
```

只允许读取：

```text
cns_rpi/%u/config/set
cns_rpi/%u/control/set
```

因此通过认证的设备也不能冒充其他 `vendor_id`。

### 4.2 route_service 账户

`route-service` 使用独立服务账户，允许：

- 读取所有设备 registration、telemetry、config ACK 和 control ACK；
- 读取固定来源的 config/control request；
- 发布设备 config/control set；
- 发布来源 ACK 和规范化设备状态事件。

Broker ACL 是连接身份与 topic 权限的第一道边界；route_service 的 `command_sources`、设备同校约束、来源权限、寻址和幂等校验仍是第二道业务边界，二者不能互相替代。

### 4.3 backend_service 账户

`web-console` 账户只允许：

- 发布 `cns_rpi/sources/web-console/config/request`；
- 发布 `cns_rpi/sources/web-console/control/request`；
- 读取 `cns_rpi/sources/web-console/config/ack`；
- 读取 `cns_rpi/sources/web-console/control/ack`；
- 读取 route_service 发布的规范化设备状态事件。

该账户不能直接发布设备 set，也不能伪造其他 `source_id`。backend_service 的用户账号和学校权限仍由 backend_service 自身鉴权处理。

### 4.4 人工联调账户

建立独立 `manual-test` MQTT 账户和 `command_sources` 记录：

- 只允许发布 `sources/manual-test` 的 config/control request；
- 只允许读取 `sources/manual-test` 的 config/control ACK；
- 默认禁用，需要联调时人工启用；
- 不复用 `web-console` 密码，不直接获得设备 set 权限。

## 5. 客户端配置与行为

route_service 和 cns_rpi 的 MQTT 配置增加 TLS 段：

```json
"tls": {
  "enabled": true,
  "ca_file": "/etc/cns/certs/cns-root-ca.crt"
}
```

要求如下：

- `enabled=true` 时，CA 文件必须存在、可读且能被 TLS 库加载。
- 客户端使用系统证书校验和目标 IP 校验。
- TLS 配置错误属于终止性配置错误，进程输出中文诊断并退出，不进入无限重连。
- 已成功初始化后的暂时网络中断继续使用现有 MQTT 重连策略。
- 认证失败、ACL 拒绝和证书错误不得输出密码、token、私钥内容或完整连接串。
- 示例配置只包含占位路径和空密码，真实值保存在仓库外。

树莓派和 route_service 当前已有用户名/密码支持，但尚无 TLS 初始化；两端都需要增加 libmosquitto TLS 配置、配置校验和测试。

## 6. frp 0.70.0

frps 与 frpc 必须使用相同的 `0.70.0` 版本和 TOML 配置。

### 6.1 frps

- 强制 `transport.tls.force = true`；
- 使用独立 frps 证书、私钥和 CNS 根 CA；
- 使用随机 token 认证，token 从权限为 `0600` 的独立文件读取；
- token 验证覆盖登录、心跳和新工作连接；
- `allowPorts` 只允许 `8883`；
- `maxPortsPerClient = 1`；
- 不启用公网 Dashboard、vhost HTTP/HTTPS、KCP、QUIC、pprof 或其他无关入口。

### 6.2 frpc

- 严格验证 frps 证书链和弹性公网 IP；
- token 从权限为 `0600` 的独立文件读取；
- 只建立一个 TCP proxy：本地 `127.0.0.1:8883`，远端 `8883`；
- 由 systemd 管理，异常退出自动重启；
- frpc 不终止 MQTT TLS；frpc 启动失败不改变本地 Mosquitto 或 route_service 状态。

## 7. 文件与秘密管理

建议现场路径：

```text
/etc/cns/
├── route_service.json
├── certs/
│   └── cns-root-ca.crt
└── mqtt/
    ├── broker.crt
    ├── broker.key
    ├── passwd
    └── acl

/etc/frp/
├── frpc.toml
├── token
└── certs/
    └── cns-root-ca.crt
```

树莓派只持有公开根 CA、自己的 MQTT 用户名和密码，不持有 CA 私钥。真实密码、token、证书私钥、现场配置及数据库目录不得提交 Git。所有秘密文件必须仅允许对应服务账户读取。

## 8. 切换与回退

允许部署切换期间设备离线几分钟，不建设双链路无缝迁移：

1. 完成两端代码、配置模板、证书脚本和自动化测试。
2. 生成 CA、Mosquitto/frps 叶证书和独立账户。
3. 验证 Mosquitto 本地 TLS、认证和 ACL。
4. 验证 frpc/frps 控制链路。
5. 从公网验证弹性公网 IP `8883` 的 Broker 证书。
6. route_service 切换到本地 TLS `8883`。
7. 逐台更新树莓派 CA、弹性公网 IP、端口和独立凭据。
8. 验证 registration、telemetry、配置命令和非破坏性飞控命令链路。
9. 关闭旧匿名 listener。
10. 硬件服务器恢复后按相同流程迁移。

失败时停止 frpc 并恢复旧局域网配置。回退不得删除数据库、清空 Broker 数据或覆盖设备已有配置备份。

## 9. 验收标准

自动化和本机隔离集成测试必须证明：

- 两端 TLS 配置解析、加载和错误分类符合设计；
- 正确 CA、目标 IP、用户名和密码可以连接；
- 错误 CA、错误目标 IP、错误密码和匿名连接均失败；
- 设备不能读写其他设备 topic；
- `web-console` 和 `manual-test` 不能直接写设备 set；
- `manual-test` 不能伪造 `web-console`；
- route_service 可以完成全部必要订阅与发布；
- TLS 重连后 retained registration、遥测、配置命令和飞控命令行为不改变现有业务协议；
- 日志不泄露秘密。

本机综合验收还必须覆盖树莓派经弹性公网 IP、frps、frpc、Mosquitto、route_service 到 ACK 回程的完整链路。真实飞控只执行用户明确授权的非破坏性命令。

现场服务器不可用时，现场 PostgreSQL、Mosquitto、frpc 和 systemd 验收必须明确延期，不能用开发机结果推定通过。

## 10. 文档与实施边界

本设计是 Route Service V1 里程碑五的全局部署指引，直接放在 `route_service/docs/`。确认后应先编写详细实施计划，再从最新主线建立隔离工作树执行。

实施必须同步：

- route_service 配置、TLS 客户端、部署模板、测试和说明；
- cns_rpi 配置、TLS 客户端、部署说明和测试；
- Mosquitto ACL、密码文件生成和证书生成流程；
- frps/frpc 示例配置与 systemd 部署；
- backend_service 固定 `web-console` MQTT 身份和权限边界；
- 顶层 README、子项目 README 和最终验收记录。

任何真实秘密只在仓库外生成和部署。未经用户授权，不修改云服务器、现场服务器、开发机系统服务或树莓派运行状态。
